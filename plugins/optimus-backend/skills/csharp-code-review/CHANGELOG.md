# Changelog

## [1.7.1] - 2026-11-14

### Fixed
- 依 Microsoft Learn 官方文档核对并修正 references 中的事实性错误：`lock` 内 `await` 为 CS1996；typed HttpClient 为 Transient；`Memory<T>` 非 ref struct；MemoryCache `SizeLimit` 须配 `entry.SetSize`；`ConcurrentDictionary` 委托在锁外执行且枚举器非快照；字符串插值不会编译为 StringBuilder；匿名类型为堆上引用类型；`Directory.Build.props` 早期导入故项目属性条件应放 `.targets`；日志参数始终先求值（须 `IsEnabled` 守卫）；序列化器安全清单；MSTest `DataTestMethod` 已不推荐；`dotnet test` 不向上查找、MTP 用 `--project/--solution`

## [1.7.0] - 2026-11-14

### Added
- `references/02-coding-style.md` § 2.1 新增类内成员顺序规则（应该）：字段 → 构造函数 → 属性 → 命令（仅 MVVM / UI）→ 公开方法 → 受保护方法 → 私有方法 → 事件处理方法，并附示例与 § 4 速查行。`#region` 定为可选（可以用、不要求）：依据微软文档仅将其定位为编辑器折叠工具、StyleCop SA1124 将其列为应避免项；规则同时禁止用 region 折叠整齐来代替拆分过大的类
- 新增 `using` 规则：禁止用 `#region` 包裹 `using`、必须移除无用 `using`、排序与 IDE「Remove and Sort Usings」默认一致（`System.*` 优先，其余按字母升序）；大小写次序与 `global using` / `using static` / 别名 `using` 的排序交 IDE 自动整理，审查时不据此判违规（审查只判可目视核对的项，因本 skill 无法运行 IDE）

### Changed
- `test-prompts.json` 删除重写：原三条与新规则无关的用例（命名/拼接、合规 async、async void）换成三条覆盖新规则的用例（乱序 ViewModel 含 region 包 using、合规代码含 region 与 using static/别名 using、async void/.Result/空 catch 回归）
- 反例黑名单新增一条：「修正后的代码」里调整 `using` 时不得丢掉仍被用到的项、不得保留无用项、须按 § 2.1 排序（针对实测中修正稿丢 `using`、多出无用 `using`、排序错误的失误）
- § 2.1 原「成员间保留空行（字段 → 构造函数 → 属性 → 方法）」去掉括号内的顺序说明，改由成员顺序条款统一规定
- § 2.1 原「`using` 置于命名空间之外，`System.*` 优先排序」拆为「置于命名空间之外」与独立的排序条款，排序口径不变（`System.*` 优先），并明确与 IDE 默认一致
- 审查清单 #4 核对要点与快速初审第 4 条同步补充成员顺序（`#region` 可选）与 `using` 要求；快速初审第 4 条补上「无无用 `using`、排序与 IDE 一致」

### Fixed
- `SKILL.md` 流程与 `allowed-tools: Read Grep Glob` 不符：第 2 步原写「用 `git diff`」、第 4 步原写「落盘」，而该 skill 既无 Bash 也无 Write 权限；改为请用户提供 diff/改动清单、报告直接呈现，权限声明不变
- `02-coding-style.md` § 4 成员顺序行原称「违规」，与该条「应该」级不符，改为「偏离建议顺序（应该级）」；§ 2.1/§ 2.2 示例中的单行 `{ }` / `if (...) { throw ...; }` 原违反同文件的 Allman 规则，改为展开写法；§ 1.2 示例 `FileExists` 非动词前缀布尔属性，改为 `HasFile`
- 删除失败表中逐字重复的两行（「严重级别判定存在歧义」「`修正后的代码` 用到 C# 9+ 新语法」各出现过两次），不改变任何规则内容
- § 2.4 与 § 4 速查中 `var` 掩盖类型的示例原以 `object data = GetComplexData();` 作修复写法，而 § 1.2 明令禁止 `data` 这类无意义命名，规则自相矛盾；示例改为 `var report = …` → `OrderReport report = …`，与 § 2.4 已有示例一致
- § 2.1 把 `using` 示例与成员顺序示例塞在同一代码块，两个主题混在一起，拆成两个代码块；`using` 排序条款原写「其余按字母升序」又写「大小写次序不判违规」，两处口径冲突，前者补上「大小写次序以 IDE 为准」；§ 2.3 示例 `string result = ""` 与 § 2.4「类型从右侧可见时用 `var`」冲突，改为 `var result = ""`
- § 2.3 ❌/✅ 示例同在一个代码块且都声明 `var result`（同作用域会重复声明），拆为两个代码块；§ 2.1 成员顺序示例补上受保护方法，与类别清单一致；`SKILL.md` 审查清单第 2 行 `\|\|` 转义以免破坏表格列；清单 #4 与快速初审第 4 条的核对要点缩短，语义不变
